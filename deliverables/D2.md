# **D2. Requirements**
# **Positioning**
### *1.1 Problem Statement*
*The problem of the lack of learning in games affects the players; the impact of which is that players cannot sharpen their problem solving skills.*  

### *1.2 Product Position Statement*
*For players who want to discover learning machinery in CircuitWorks, a video game, that teachers players how to create machines and link circuits which supports problem solving skills; unlike Mega Factory Tycoon, our product does not rely on premade machines that do not require any input by the player to build.*  

### *1.3 Value propoosition and customer segment*
**Value proposition**: *CircuitWorks is a game that gives players the freedom to strengthen their problem solving skills by allowing them to create complex curcuits that supports custom programming within the game all wrapped up in a fun environment.* 

**Customer segment**: *People who play video games to enjoy learning by themselves or to teach a family member.*

# **2. Functional requirements**
1. Program Circuits with a microcontroller system
2. Connect circuits with eachother
3. Machines react to cuircuits
4. Machines produce items  
5. Gather resources
6. Process raw resources
7. Mine for raw materials
8. Create conveyor belt systems
Change direction, speed, item capacity, input.output
9. Generate power
10. Distribute electricity to machines
11. Control power with switches
12. Manage available power
13. Use sensors for items, storage, power, and machines
14. Provide an end goal A: buying, selling supplies, reach $1 million dollars
15. Proivide an end goal B: build a megaproject to connect a remote colony with the rest of humanity
16. Save the users progress  

# **3. Non-functional requirements**
1. Compatibility: Users can play the game on their personal desktop as well as on a laptop  
2. Usability: Users will spend no longer than 60 minutes when learning a new machine/circuit for the first time.  
3. Usability: Users will spend no longer than 2 seconds for a ui element to update such as an inventory. 
4. Usability: Users will locate all UI elemnts with 20 seconds after seeing the game UI and world UI for the first time.
5. Performance efficiency: The game will not drop below 60fps when running it on desktop or laptop computer with hardware from the last 5 years
6. Readability: UI text will be clear to read by making a large font with 60px size and avoiding collision with 80 pixels of space between other text  


# **4. MVP**  

The MVP for CircuitWorks will be a small interactive game where players can build circuits and write Python code to control them. The game will provide an environment where players can experiment with different circuit components and programming commands while building and expanding a factory.

This MVP is enough to validate the value proposition because it tests the main purpose of CircuitWorks: whether players can learn about circuits and Python while having fun and being creative. Players do not need a large world or many advanced features to test this. If they can create circuits, write code, build their factory, and experiment with different solutions, the MVP will show that CircuitWorks can combine learning, creativity, and gameplay.

### ***5.2 Use case descriptions and interface sketch***  

Use Case 1: Build a Circuit
Primary Actor: Player

Goal: The player builds and connects circuit components in order to control machines.

Preconditions:
 - The selected circuit components are placed and connected
   
Main Success Scenario:
 - Player: Chooses to build a circuit.
 - System: Displays the available circuit components.
 - Player: Selects a circuit component.
 - System: Shows valid locations where the component can be placed.
 - Player: Selects a location.
 - System: Places the component.
 - Player: Selects another component or machine to connect.
 - System: Displays available connection points.
 - Player: Selects the desired connection.
 - System: Creates the circuit connection.

Alternative Flow:
 - If the selected location and/or connection is invalid, then the system informs the player and allows a different seelction.

Use Case 2: Program a Microcontroller
Primary Actor: Player

Goal: The player creates a program that controls connected machines or circuits.

Preconditions:
 - A microcontroller has been placed.
 - At least one device is connected to it.

Postconditions:
 - The program is stored and can control connected devices.

Main Success Scenario:
 - Player: Selects a microcontroller.
 - System: Displays the current program and connected devices.
 - Player: Provides Python instructions.
 - System: Checks the program.
 - System: Confirms that the program is valid.
 - Player: Requests that the program run.
 - System: Executes the program.
 - System: Controls the connected devices.

Alternative Flow:
 - If the program contains an error, the system identifies the problem and allows the player to revise the program.

Use Case 3: Process Resources
Primary Actor: Player

Goal: The player processes raw resources into useful materials.

Preconditions:
 - Raw resources are available.
 - A processing machine is available.
 - The machine has access to power.

Postconditions:
 - Processed materials are produced.

Main Success Scenario:
 - Player: Supplies raw resources to a processing machine.
 - System: Detects the available resources.
 - System: Checks that enough power is available.
 - System: Processes the resources.
 - System: Produces the finished material.
 - System: Makes the material available for transport or storage.

Alternative Flow:
 - If resources or power are unavailable, the system pauses processing and informs the player.

Use Case 4: Save Progress
Primary Actor: Player

Goal: The player saves the current game state for later use.

Preconditions:
 - A game session is active.

Postconditions:
 - The player's current progress is stored.

Main Success Scenario:
 - Player: Requests to save the game.
 - System: Records the current factory state.
 - System: Records circuits, machines, resources, programs, and player progress.
 - System: Stores the saved game.
 - System: Confirms that the save was successful.

Alternative Flow:
 - If the save cannot be completed, the system informs the player and keeps the current session active.

Use Case 5: Build a Conveyor System
Primary Actor: Player

Goal: The player creates a conveyor system to move items between machines.

Preconditions:
 - The player has access to conveyor components.
 - Machines or storage areas are available to connect.

Postconditions:
 - Items can move automatically between connected locations.

Main Success Scenario:
 - Player: Chooses to build a conveyor system.
 - System: Displays available conveyor components.
 - Player: Selects a conveyor component.
 - System: Shows valid placement locations.
 - Player: Selects where the conveyor should be placed.
 - System: Places the conveyor.
 - Player: Connects the conveyor to machines or storage.
 - System: Confirms the conveyor path.
 - System: Moves items through the completed system.

Alternative Flow:
 - If the conveyor path is invalid or blocked, the system informs the player and allows another placement.

Use Case 6: Generate and Distribute Power
Primary Actor: Player

Goal: The player provides power to machines and circuits.

Preconditions:
 - A power source is available.
 - Machines or circuit components require power.

Postconditions:
 - Connected machines and circuits receive electricity.

Main Success Scenario:
 - Player: Chooses a power source.
 - System: Displays available power-generation options.
 - Player: Places the power source.
 - System: Shows available power connections.
 - Player: Connects the power source to machines or circuits.
 - System: Calculates available and required power.
 - System: Distributes power to the connected devices.
 - System: Displays the current power status.

Alternative Flow:
 - If power demand is greater than the available supply, the system warns the player and identifies devices that cannot operate.
